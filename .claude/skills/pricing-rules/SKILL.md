# 定價心法

> 這是**挖空模板**。標 ★ 的地方要你自己填，每一條都要寫「理由」。
> 填的內容來自你自己玩遊戲的經驗：哪些價格客人會買、哪些會嫌貴、星等怎麼變。

## 什麼時候用

AI 店長要決定某一天每樣菜的定價時。

## 一定要遵守的規則（來自規則書，不可以改）

- 定價只能在菜單的可定價範圍內（見 `web-lab/src/game/menu.js` 的 minPrice～maxPrice）
- 客人只有在「價格 ≤ 剩下的預算」時才會買
- 價格 ≤ 建議售價，客人買到第一順位才會「滿意」；滿意的人多，星等才會升

## 我的定價心法

心法 1（什麼時候該定在建議售價以下？）：只有在有實際試算或盤點結果支持時才降價——例如上一版資料顯示這道菜「嫌太貴」的客人很多，或是這次就是想驗證「降價能不能提高滿意度／來客數」這個假設時，才把價格調到建議售價以下測試。
理由：降價會犧牲每份的收益（成本不變、單份賺的錢變少），不能只憑感覺降價。要先有「嫌太貴」之類的實際觀察當依據，才知道降價是在解決真正的問題，而不是平白損失利潤。這是本次教學要驗證的策略假設，不是已經證明有效的經營規律。

心法 2（什麼時候可以漲價？漲到多少？）：只能漲到規則書菜單「可定價範圍」的上限以內，而且要先說清楚這次漲價想驗證什麼（例如想測試漲價對購買、滿意度、後續來客數的影響），漲多少、為什麼漲這麼多都要寫出來。
理由：價格一旦超過建議售價，原本能「滿意」的客人會變成「普通」，滿意比例下降會讓星等往下掉、進而影響隔天來客數；價格也可能超過客人剩下的預算，導致買不到（賣出變少）。看到「缺貨」（賣完後沒買到）只代表需求大於備貨，**不能直接當成「漲價一定有效」的證據**——缺貨該解決的可能是備貨量不夠，不一定是價格太低，漲價前要先想清楚這點。

心法 3（第一版策略怎麼定價？）：第一版（基準版）一律用規則書菜單上的「建議售價」，不漲也不跌。
理由：建議售價是中性的比較基準。如果第一版就先調價，之後看到淨利變化時會分不清是「調價」造成的、還是備貨量或宣傳費造成的；要先有一版「全部用建議售價」的結果當對照組，之後每一版只調一兩個變項（例如只改某一樣菜的價格），才看得出哪個改動真的有效。

